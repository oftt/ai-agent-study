# Stage 4 · 记忆 Memory

> 日期:2026-08-18 · 状态:✅ 完成 · 源码:`stage04-memory/` + 公共库 `lib/`

## 🎯 阶段目标

- 短期记忆:滑动窗口(最简单)与摘要压缩(不丢关键信息)
- 长期记忆:向量检索记忆(跨对话记得住)
- 顺带完成一次**架构重构**:抽出公共库 `lib/`(llm 客户端、embedding)

**背景问题**:`messages` 无限增长会撑爆模型上下文窗口。怎么办?—— 按"记忆层次"分层管理。

---

## 🧠 记忆的三层金字塔

```
┌─────────────────────────────────────┐
│  长期记忆(向量库)  跨对话,存事实     │  Stage 4 第三部分
├─────────────────────────────────────┤
│  近期记忆(最近几轮) 当前对话的细节    │  Stage 4 一、二部分
├─────────────────────────────────────┤
│  系统提示词(人设)  永远保留           │
└─────────────────────────────────────┘
```

---

## 1️⃣ 滑动窗口(`buffer_memory.py`)—— 最简单

### 实现:内存里只留最近 N 条

```python
def add(self, role, content):
    self.messages.append({"role": role, "content": content})
    if len(self.messages) > self.max_messages:      # 超窗
        excess = len(self.messages) - self.max_messages
        self.messages = self.messages[:1] + self.messages[1 + excess:]  # 丢最旧,留 system
```

### 运行结果(对比实验)

| | 第 3 轮(推荐餐厅) | 第 4 轮(我住哪个城市?) |
|---|---|---|
| **小窗口 max=2** | "您能告诉我所在城市…" ← 忘了 | **"我记不住…不会保存你的个人信息"** |
| **大窗口 max=100** | "既然你在上海,我推荐…" ← 记得 | **"你之前提到住在上海,我记住了"** |

> 一个细节:小窗口到第 3 轮已经忘了用户住上海,所以推荐餐厅时**反问你所在城市**——这既是缺点(没上下文)也侧面说明模型只依赖给的上下文。

## 2️⃣ 摘要压缩(`summary_memory.py`)—— 聪明一点

### 思路

滑动窗口是"硬砍",摘要压缩是"压缩":窗口满了,让模型把老对话**概括成一段摘要**,之后每次带:摘要(远古) + 最近几轮(近期)。

```python
class SummaryMemory:
    def _rollup(self):                              # 触发压缩
        transcript = "\n".join(f"{m['role']}: {m['content']}" for m in self.recent)
        new_summary = 调用模型("把这段对话压缩成摘要,保留个人偏好/承诺…", transcript)
        self.summary += new_summary                  # 摘要累加
        self.recent = []                            # 清空近期
```

### 运行结果

用户说了"我是程序员,在学 AI Agent""喜欢美式咖啡不加糖"后,经过多次压缩:

```
🗜️ 摘要: 用户是程序员,正在学习 AI Agent;喜欢美式咖啡且不加糖……
[第 5 轮] "我最近在学什么?"  → 你在学 AI Agent ✅(来自摘要)
[第 6 轮] "我喝咖啡喜欢加什么?" → 美式咖啡,不加糖 ✅(来自摘要)
```

**代价**:每压缩一次要调用一次模型(几厘钱),但换来"不忘关键信息"。

## 3️⃣ 长期记忆:向量检索(`vector_memory.py`)

### 为什么需要它

短期记忆只管"当前对话"。长期记忆要解决:**下次会话**用户问"我以前说过什么",Agent 还能想起。

### 三步原理(这就是"迷你 RAG"!)

```
① 存储  事实 → embedding 向量 → 存起来
② 检索  问题 → embedding → 与所有记忆算余弦相似度 → 取最相关的 top_k
③ 注入  检索结果塞进 system → 模型回答时参考
```

### 运行结果(检索打分)

| 问题 | 命中的记忆 | 相似度 |
|------|-----------|--------|
| 他喜欢喝什么? | 小明喜欢喝美式咖啡,不加糖 | 0.51 |
| 我什么时候过生日? | 用户小明的生日是 3 月 14 日 | 0.54 |
| 他在减肥吗? | 小明最近在健身,目标是减重 5 公斤 | 0.60 |
| 关于他的猫? | 小明有一只叫「团子」的橘猫 | 0.55 |

四个问题全部命中正确答案,回答全部正确。**这就是"记得住上个月聊过什么"的原理。**

## 🏗️ 架构重构:公共库 `lib/`

Stage 4 开始,多个脚本都要"创建 LLM 客户端""做 embedding"。与其每处复制,不如抽成公共库:

```
ai-agent/
├── lib/
│   ├── __init__.py     # 公共库标记
│   ├── llm.py          # get_client() + MODEL(懒加载单例)
│   └── embed.py        # embed()/embed_many(),fastembed 封装
└── stage04-memory/     # 各脚本 import lib
```

脚本顶部用一行把项目根加入 `sys.path`,即可 `from lib.llm import ...`:

```python
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))
```

> 💡 **这是工程思维**:代码可复用就抽公共模块,Stage 5 的 RAG 会继续用 `lib.embed`。

### Embedding 选型

- **fastembed**:ONNX 运行时,无需安装庞大的 PyTorch(~2GB)
- 模型 `BAAI/bge-small-zh-v1.5`:中文效果好、体积小(~55MB),首次自动下载
- 国内下载:`HF_ENDPOINT=https://hf-mirror.com` 走镜像

## 🕳️ 踩坑记录

| 坑 | 现象 | 解法 |
|----|------|------|
| fastembed 把 `h11` 降到 0.14 | openai SDK 报错/返回空 | `pip install "h11==0.16.0"` |
| 环境里混入 torch 用户包 | 依赖冲突警告 | 忽略(我们不依赖 torch),只保证 h11 版本正确 |
| 滑动窗口保护了第一条 | 演示"遗忘"失败 | 把 system 放进消息流只保护 system,老消息真被丢弃 |

## ✍️ 动手练习

1. 把 `buffer_memory.py` 的 `max_messages` 从 2 调到 3~5,观察"遗忘"在哪一轮开始
2. `summary_memory.py`:在对话中埋一个"承诺"(如"我明天要交周报"),看摘要是否保留、后续能否答对
3. `vector_memory.py`:往记忆库加 3 条你的真实信息,问 3 个相关问题,看检索打分是否合理

## 📌 小结

> **记忆 = 分层管理:system 保人设,滑动窗口保近期,摘要保关键,向量库保长期。**
> 而"向量检索记忆"本质上就是 RAG—— 下一阶段,我们把同样的技术用在外部的**文档知识库**上,让 Agent 从"记得住"进化到"查得到"。

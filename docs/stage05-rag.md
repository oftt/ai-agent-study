## 🧠 RAG 全景:一句话

> RAG = 先**检索**外部资料,再让模型**基于资料**回答。
> 模型不再凭记忆硬答,而是"先查资料再说话",从根上解决**幻觉**和**知识过时**。

```
        ┌───────────── 离线阶段(一次构建,反复使用) ─────────────┐
 文档 ──→ 分块 ──→ embedding ──→ 向量库存储                     │
        └───────────────────────────────────────────────────────┘
        ┌───────────── 在线阶段(每次提问都走) ──────────────────┐
 问题 ──→ embedding ──→ 向量库检索 top_k ──→ 拼进提示词 ──→ 模型生成回答
        └───────────────────────────────────────────────────────┘
```

## 1️⃣ 入库(`ingest.py`)

### 分块(Chunking)—— RAG 的第一个细节

问题:模型上下文有限,塞不下整本手册;检索是"按片段"找的。

```python
def chunk_text(text, chunk_size=250, overlap=40):
    chunks = []
    start = 0
    while start < n:
        end = min(start + chunk_size, n)
        chunks.append(text[start:end])
        start = max(end - overlap, start + 1)   # ← 重叠:相邻块共享 40 字
    return chunks
```

- **太大** → 一个片段混入多个主题,检索噪音大
- **太小** → 片段信息不完整,答案断章取义
- **重叠(overlap)** → 句子的尾巴不会因切分而断裂

运行结果:1435 字 → **7 个片段**。

### 向量库(`vector_store.py`)

课堂版用 numpy 手写,把向量存成矩阵,检索用**矩阵点积**(一次算全部相似度):

```python
qn = qv / norm(qv)                       # 问题向量归一化
vn = V / norm(V, axis=1)                 # 全部片段向量归一化
scores = vn @ qn                         # 余弦相似度 = 归一化点积,一行算完
idx = np.argsort(-scores)[:top_k]        # 取最高 top_k
```

`save()/load()` 把 `chunks.json + vectors.npy` 存盘 → 建好索引后无需重复 embedding。

> 💡 真实项目用 ChromaDB / Milvus / Qdrant 等专用向量库,**原理完全一样**:都是"存向量 + 算相似度 + 取 top_k"。

## 2️⃣ 问答(`rag_qa.py`)—— 三段式

```python
# RETRIEVE
hits = store.search(question, top_k=3)          # 1. 检索相关片段

# AUGMENT
context = "\n\n".join(f"[片段{i+1}] {text}" ...) # 2. 拼成"参考资料"
prompt = f"严格依据资料回答,资料没有就说'资料里没有提到'。\n资料:\n{context}\n\n问题:{question}"

# GENERATE
resp = client.chat.completions.create(..., temperature=0.2)   # 3. 低温生成
```

两个关键设计:
- **temperature=0.2** —— 问答求准不求创意
- **明确约束**"资料没有就说没有" —— 这就是**防幻觉**的提示词开关

## 💻 运行结果(真实)

| 问题 | 检索命中(相似度) | 回答 |
|------|-----------------|------|
| 带薪年假几天? | 请假片段 **0.68** | ✅ 10 天 |
| 出差住宿标准? | 报销片段 **0.59** | ✅ 一线 500 / 其他 350 |
| 考勤迟到怎么处理? | 考勤片段 **0.59** | ✅ 30 分钟/1 小时规则 |
| 晋升条件? | 晋升片段 **0.67** | ✅ 任职满 1 年 + 绩效 B |
| 楼下咖啡店叫啥? | (无相关片段) | ✅ **"资料里没有提到"** |

**第 5 问是灵魂**:知识库里没有,模型没有瞎编,而是诚实说"没有"。这就是 RAG 的价值——**可控、可溯源、不幻觉**。

## 🕳️ 踩坑记录

| 坑 | 说明 | 解决 |
|----|------|------|
| fastembed 每次报 "Could not download from HF" | 镜像直连失败的噪声日志,实际回退成功 | 忽略;模型已缓存到 `lib/.models` |
| 模型缓存默认在系统临时目录 | 重启可能被清理、反复下载 | `FASTEMBED_CACHE_PATH` 指向项目内 `lib/.models` |
| 分块把句子切两半 | 片段开头是上一段结尾 | 用 overlap 缓解(40 字) |
| PowerShell 显示 NativeCommandError | `2>&1` 捕获 stderr 的噪声 | 不影响运行,忽略 |

## 📌 小结

> **RAG = 分块 + 向量化 + 检索 + 提示词约束。你已拥有一套"查得到、不幻觉"的文档问答系统。**
> 但向量检索还有短板:同义词、缩写、数字类问题可能召不回(召回率不够),多主题混合问题答得不准。下一阶段解决这些 —— 混合检索 + 重排序 + 评估。

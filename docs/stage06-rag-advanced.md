## 1️⃣ BM25 关键词检索(`bm25.py`)—— 为什么需要它

向量检索按"语义"找,**遇到精确术语/缩写/数字就抓瞎**。举例:

- 查「OA 系统」→ 向量可能检索到语义相近但没这个字眼的片段
- 查「年假 10 天」→ 向量不知道"10"是精确数字

BM25 是传统信息检索的常青树,按**字面命中**打分,恰好补足这一路。

### 核心公式(理解它,别背它)

```
score(d,q) = Σ  idf(q) × tf(q,d)(k1+1) / [ tf(q,d) + k1(1 − b + b·|d|/avgdl) ]
```

| 记号 | 含义 | 直觉 |
|------|------|------|
| `tf(q,d)` | 词 q 在文档 d 出现次数 | 出现越多越相关 |
| `idf(q)` | 词 q 有多稀有 | 满篇都是的词没价值("的""了") |
| `k1` | 词频饱和系数 | 防止"出现 100 次"分数无限涨 |
| `b` | 长度归一化 | 长文档不该天然高分 |

分词用 `jieba`(把"员工手册"切成词才能统计词频)。

## 2️⃣ 混合检索 + RRF(`hybrid_store.py`)

### RRF(Reciprocal Rank Fusion)倒数排名融合

两路检索各自返回排名,但**分数不在一个量纲**(向量分 0.5,BM25 分可能上千)。直接加权会失衡。RRF 巧妙的解法:**只看名次**:

```python
fused[i] += 1 / (k + rank + 1)     # 两路都排第1的,融合分最高
```

把每路的前 10 名折算成分数相加,再按总分排序 → 两路都认可的片段排最前。

### 元数据过滤

分块时记录"所属章节",检索后可定向:

```python
def filter_by_meta(self, ids, keyword):
    return [i for i in ids if keyword in self.metas[i]]   # 只留"报销"章节的
```

### LLM 重排(Cross-Encoder 的国内平替)

真实项目常用 bge-reranker 等交叉编码器重排,但需要额外模型。国内环境用**模型重排**替代:

```
让模型看 问题 + 候选片段,输出 {"order": [编号...]} 挑最相关的 top3
```

把检索从"初步召回 top5"精排到"最相关 top3"。

## 💻 运行结果(真实)

### 演示(`demo.py`)

- **元数据过滤**:"住宿标准" 混合召回 8 个片段 → 过滤后只剩「报销制度」1 个 ✅
- **LLM 重排**:"年假能休几天" 候选 5 个 → 重排后两个「请假制度」片段排最前 ✅

### 评估(`evaluate.py`)—— 用数据说话

| 方法 | Recall@3 | MRR |
|------|----------|-----|
| 纯向量 | 1.00 | 0.93 |
| **混合 RRF** | **1.00** | **1.00** |

**诚实解读**:
- 这个小手册只有 11 个片段、章节区分明显,纯向量已经很能打 → **混合检索的优势不明显**
- MRR 0.93→1.00 的差异,来自某条查询的黄金片段被从第 2 名提到了第 1 名
- **混合检索真正发力的场景**:① 语料库大(上万片段);② 含精确术语/编号/数字的查询;③ 片段主题区分不明显的场景。这些场景下 BM25 的字面命中能救回向量漏掉的

> 这个"改进不明显"本身就是一次真实的教学:评估不是为了证明"我改得对",而是**诚实量化改进**。如果改进微弱,就该反思——这是工程思维。

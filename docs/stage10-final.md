## 🔍 三个关键设计

### 1. RAG 作为"工具",而不是独立系统

知识库问答的最终形态,是把检索**封装成一个工具**喂给 Agent:

```python
self.tools_impl = {
    "search_knowledge": kbase.search_knowledge,   # ← RAG 是 Agent 的一只手
    "get_current_time": get_current_time,
    "calculate": calculate,
}
```

于是 Agent 能**自己决定**何时查知识库、何时算数、何时只凭常识回答 —— 这才是"智能"。

### 2. 复用自己的代码 = 站在自己的肩膀上

- `knowledge_base.py` import 了 Stage 6 手写的 `bm25.py`
- `agent.py` import 了 Stage 9 的 `usage.py`
- 前端直接复用 Stage 9 的页面

> 毕业项目不需要从零写 —— **能把之前攒的积木组装成产品,本身就是能力。**

### 3. 流式 + 工具 + 记忆 三合一

`stream_chat` 一个生成器里同时处理:流式文本块(SSE)、静默工具调用、多轮记忆裁剪、用量累加。这就是 Stage 9 的 ChatAgent 在真实产品中的形态。
